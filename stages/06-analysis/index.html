Sample data for design review.

01 · What

Turn governed data into answers

Analysis is where the value in data is found. Analysts do most of it, data scientists take on predicting and recommending, and business stakeholders supply the goal.

Tools: Machine learning and language models.

02 · How

Ask four questions

What happened, why, what will happen, and what to do. These are four kinds of analysis: descriptive, diagnostic, predictive and prescriptive.

Tools: Machine learning and language models.

03 · Why

So the answer can be trusted

A goal keeps the work on a real question. A trace lets anyone follow an answer back through the stages to the row it began as.

Tools: Lineage and audit trail tools.

04 · When

When someone has a question

A stakeholder brings a goal, such as whether patients wait too long. The data is already described and protected from Stage 5, so analysts can start at once.

Tools: Machine learning and language models.

05 · Next

Descriptive: what happened

The first question is the simplest. Analysts summarize what the Silver row says happened.

Tools: Machine learning and language models.

01 · What

Summarize the past

First, the Silver rows are shaped into a Gold table, a business-ready table made for one question. Totals, averages and counts then say what happened. Analysts own it.

Tools: Machine learning and language models.

02 · How

Count, average, compare

Analysts average the Gold table by month and compare. Sample: wait was 34 minutes this month against 28 last month. The shaded band marks the normal range.

Tools: Machine learning and language models.

03 · Why

Agree on what happened first

Nobody can ask why, or what next, until the past is clear. A plain summary gives every later question something to stand on.

Tools: Machine learning and language models.

04 · When

Every reporting cycle

Each month an analyst reads the data for the report. Stage 5's audit log already records that read.

Tools: Machine learning and language models.

05 · Next

Diagnostic: why it happened

November's wait is above the normal range. The next question is why.

Tools: Machine learning and language models.

01 · What

Find the cause

A diagnostic question looks behind a result to what drove it. Analysts own it. November's wait is above the normal range, so the question is why.

Tools: Machine learning and language models.

02 · How

Split it, then read what patients said

Analysts split the wait by clinic, then read what patients wrote in their survey. Sample: Clinic B waited 45 minutes, the others about 28, and its comments mention lab results.

Tools: Machine learning and language models.

03 · Why

A cause points to a fix

Knowing what happened is not enough to act. A cause points to a fix instead of a guess, and an analyst confirms it before anyone relies on it.

Tools: Machine learning and language models.

04 · When

When a result is out of range

The trigger is a descriptive result outside its expected range, like November. Normal results do not need a diagnosis.

Tools: Machine learning and language models.

05 · Next

Trusted definitions

A number is only useful if every report calculates it the same way. Next: how “wait time” is defined once, in one place, and checked.

Tools: Machine learning and language models.

01 · What

Define a number once

A governed definition says exactly how a metric is calculated, written in one place. Data stewards own it and analysts use it.

Tools: Machine learning and language models.

02 · How

Spot the conflict, publish one

“Wait” can be counted two ways. Sample: the monthly report says 34 minutes and a dashboard says 52. A banner flags the conflict, a steward publishes one definition, and both reports then agree.

Tools: Machine learning and language models.

03 · Why

So people keep trusting the numbers

When two reports disagree on the same thing, people stop trusting both. One definition also stops AI from reading the same term two ways.

Tools: Governance and catalog tools.

04 · When

When a metric changes or reports disagree

A definition is written when a metric is created, and revisited whenever it changes or two reports show different numbers.

Tools: Governance and catalog tools.

05 · Next

Part 2: predictive

With trusted data, a clear past, a cause and one definition, analysts and data scientists can look ahead: what will happen next.

Tools: Machine learning and language models.

01 · What

Look ahead

Predictive analysis says what will likely happen. Data scientists own it, and the model learns patterns from past rows.

Tools: Machine learning.

02 · How

Learn, tune, test, forecast

Most past rows teach the model, some tune it, and some are held back to test it. Sample: it forecasts December at about 41 minutes, give or take 4.

Tools: Machine learning.

03 · Why

Act before patients wait

A forecast lets the hospital act early. Testing on rows the model never saw shows whether to trust it.

Tools: Machine learning.

04 · When

After the past is clear, then every cycle

When the world changes, a model’s accuracy drops. This is called drift. The model is checked often and retrained.

Tools: Machine learning and model monitoring.

05 · Next

Prescriptive: what to do

A forecast says what is coming. The last question is what to do about it.

Tools: Machine learning and language models.

01 · What

Recommend an action

Prescriptive analysis weighs the options and says which best serves the goal. Data scientists own it, and business stakeholders set the goal.

Tools: Machine learning and language models.

02 · How

Compare the options

The model compares each option with the goal of cutting the wait. Sample: faster lab results bring December to 33 minutes, extra front-desk staff to 38, and doing nothing leaves it at 41.

Tools: Machine learning and language models.

03 · Why

It tells people what to do

The first three answers describe, explain and forecast. This one recommends an action, which is why a person decides.

Tools: Machine learning and language models.

04 · When

When a forecast misses the goal

It starts when a forecast shows a problem and the business has a goal to meet, such as a December wait inside the expected range.

Tools: Machine learning and language models.

Stage 7: Visualization

The answers now need to be shown clearly, so the people who decide can see them and act.
