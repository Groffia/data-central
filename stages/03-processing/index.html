Stage 3 of 8 · Data processing

Where data is prepared.

Processing makes the raw row trustworthy. At Tamsworth Health, the row from Bronze is cleaned, reshaped, joined and trimmed, then tested. Rows that pass become Silver; rows that fail wait for a person.

Sample data for design review.

01 · What

Make the raw row trustworthy

Four steps change the row, then a fifth tests it. Data engineers build the pipeline; data scientists explore the raw data first to decide what to keep.

Tools: Apache Spark for the pipeline; Jupyter notebooks for exploring.

02 · How

Clean, reshape, join, trim

Remove repeats and errors, put dates and units in one form, line up patient IDs across sources, and drop fields nobody uses.

Tools: Apache Spark jobs, scheduled and monitored by Apache Airflow.

03 · Why

Preparation is most of the work

It takes over 80% of the time on AI projects. Bad data in means bad answers out, however good the analysis looks.

Tools: Apache Airflow to orchestrate and watch the pipelines.

04 · When

Last, a quality gate

Every row is tested before it moves on. Passing rows become Silver. A failing row goes to a repair queue for a person. Nothing is silently dropped.

Tools: Validation rules in Spark jobs, run by Apache Airflow or Databricks Jobs.

05 · Next

Storage

Stage 4 keeps the Silver row safe, organized and easy to find. Bronze still holds the raw copy.

Tools: A data lake or a cloud warehouse such as Snowflake.

01 · Where

Two places AI helps

Inside the steps, where AI cleans, finds repeats and spots odd values. Around the pipeline, where an agent watches it.

02 · What

It cleans and flags

AI finds repeats, fixes formats and spots a value that cannot be right. It flags the odd value for a person; it does not delete it.

Tools: Anomaly-detection models; Apache Spark for deduplication.

03 · Why it matters

Caught before it spreads

A bad value caught here never reaches a report. A flagged row waits in the repair queue instead.

04 · Why it scales

An agent watches all day

It watches for duplicate spikes, schema changes and failed tests, and reruns or retries another way. People see only what it flags.

05 · Next

People approve repairs

The agent proposes a repair; a person approves it. Sources keep humans in the loop where accuracy matters. Clean rows flow on to Stage 4.

01 · Where

The same row, ready for AI

A model needs data prepared in extra ways. The pipeline starts from the clean Silver row and adds steps for AI use.

02 · Purge and chunk

Remove names, cut into pieces

Personal details are removed. Text is stripped of markup and cut into chunks, so a model can retrieve just the piece it needs.

Tools: Apache Spark for the purge and cleanup.

03 · Embed and index

Turn meaning into numbers

Each chunk becomes numbers that capture its meaning, stored in a vector database. A model searches it to answer from your own data (RAG).

Tools: An embedding model; a vector database.

04 · Split

Hold some rows back

About 70% of rows train the model, 15% tune it and 15% test it. A model is judged on rows it has never seen.

Tools: Apache Spark for a random split.

05 · Over time

Keep watching

Real data drifts and a model's accuracy can decay. A faulty pipeline can look like a failing model, so the pipeline is watched too. Next: Stage 4.
