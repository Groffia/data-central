Stage 1 of 8 · Data generation

Where data is born.

Before data can be collected, cleaned or analysed, something has to create it. At Tamsworth Health, that something is a bedside monitor taking a patient's vital signs.

Sample data for design review.

01 · What

A reading is created

A monitor measures a patient. One row of data now exists.

Tools: Philips IntelliVue and GE CARESCAPE monitors, into an Epic or Oracle Health EHR.

02 · How

One row, ten fields

The reading is written in an agreed shape: ten fields, the data contract.

Tools: HL7 FHIR (Observation) for the shape; dbt or Great Expectations for the contract rules.

03 · Why

Everything starts here

Every later stage trusts this row, so it is checked now. Five fields are private.

Tools: Great Expectations, Soda or dbt tests; Databricks pipeline expectations.

04 · When

Every 15 minutes

Every patient, around the clock.

Tools: Apache Airflow, Databricks Lakeflow Jobs or Microsoft Fabric Data Factory.

05 · Next

Collection

The row is ready for Stage 2 to pick up.

Tools: Apache Kafka, Azure Event Hubs or Fivetran, into Snowflake, Databricks or Fabric.

01 · Where

Two places AI helps

At the source, where rows are born. At the check, where every row is inspected.

02 · What

It makes and it watches

A generative model makes synthetic rows. An agent compares each new row to the data contract and flags problems.

Tools: GANs or LLMs for synthetic rows; an LLM-based agent for the watching.

03 · Why it matters

Caught where it starts

A bad row is stopped here, not found three stages later. Test data carries no real patient.

04 · Why it scales

Every row, every bed

People can review a sample. An agent reviews every row, all day. People only see the few it flags.

05 · Next

People review the few

Flagged rows go to a data engineer. Clean rows move on to Stage 2.
